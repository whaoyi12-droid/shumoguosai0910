# 第三问时间颗粒度与共同1月滚动的实测核查

日期：2026-09-12。按数学建模技能的实现与交付要求，核查题面、代码与实际数据，并完成共同1月预热及2月1–7日对照。正式全年求解器、旧结果和原始附件均未修改。

## 1. 小时预报的对象是光伏功率，SOC 不是小时输入

《C题.pdf》第2页问题3和附录2明确给出“未来24小时整点的光伏发电功率预报”，单位 kW；第3页要求填报十分钟购电量，单位 kWh。SOC 是依据实际充放电计算的储电量状态，不是附件中的小时预报。

当前实现链条为：每6小时获取新版本 → 各版本的整点功率分别插值到144个十分钟结束时刻 → 对相同目标时刻的新旧版本加权 → 功率乘1/6得到十分钟电量 → 优化144个十分钟购电决策 → 执行36段 → 用实际储电量进入下一次优化。

设同一版本在两个相邻整点的功率为 H_h、H_(h+1)，则第 j 个十分钟结束点（j=1,…,6）的功率为：

`P_(h,j) = (1-j/6)*H_h + (j/6)*H_(h+1)`。

例如两端分别为1200、1800 kW，则第一段结束点为1300 kW，代表该十分钟光伏电量约216.6667 kWh。这里使用项目已确认的“结束点功率代表该十分钟平均功率”离散近似。若要把插值曲线当作连续真实曲线积分，段电量应改为两端功率均值乘1/6；这是另一个假设，不能混用。

发布时刻的0小时端点来自该时刻已经结束的最近光伏观测；后续端点均来自当次已发布预报。没有拿未来整点实测值补插值。新旧版本分别插值后按目标时刻对齐，过期版本不再使用。

SOC 每十分钟递推：`S_(t+1) = S_t + 0.9*charge_kwh - discharge_kwh/0.9`。购电费依据每段实际采用的计划、调整和应急电量及该段电价核算。导出程序直接取144段账本，没有把小时费用除以6；充放电表按模板把24个十分钟段加总为4小时块，日初/日末储电量取实际轨迹端点。

代码证据：`analyze_question3_revision.vintage_matrix`、`solve_question3_six_hour.predict/optimize/simulate_day`、`prepare_question3_six_hour_workbook.prepare`。

## 2. 插值误差不能假定不存在

使用相同固定完整1月权重，评价2–12月每次发布后的最近6小时，共48096个目标；仅改变小时到十分钟的转换方式，结果如下。没有重新拟合各替代方法的权重，也没有利用评估期结果重新调参。

| 转换方式 | 光伏功率 RMSE kW | MAE kW | 每小时合计电量 RMSE kWh |
|---|---:|---:|---:|
| 当前：线性插值取段末点 | 162.7210 | 85.3073 | 140.2970 |
| 同一线性曲线按段积分均值 | 183.6971 | 105.0609 | 164.1638 |
| 下一整点功率复制为该小时六段 | 532.6325 | 297.6802 | 440.5663 |

这支持保留当前时间对齐与插值作为已有基线，不支持把小时值简单复制六次。它不是所有转换方法的最优性证明，也不能直接换算为费用优势。

另做一个明确使用事后数据的诊断：拿**真实整点光伏值**代替预报端点，再线性插值重建中间十分钟值。其2–12月重建 RMSE 仍为 **122.7102 kW**，对应逐段电量 RMSE **20.4517 kWh**，最大绝对功率误差 **1176.9358 kW**。这说明小时内变化确实无法由整点线性插值完全恢复，局部误差可能影响备用量与应急购电。

该事后重建只是分辨率诊断，不是可执行预测、不是理论误差下界，也不能把它与正式预报误差平方直接相减来分配误差来源。没有声称由这些数值已经测得全年费用的滚动近似误差。
